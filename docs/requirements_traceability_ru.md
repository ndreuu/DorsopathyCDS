# Первичные требования и проверки

Это рабочая таблица трассировки первой версии. Она помогает подготовке доказательств;
она не является полным комплектом документации для регистрации медицинского изделия.

| ID | Требование | Реализация | Проверка |
|---|---|---|---|
| CDS-001 | Воспроизводимый явный алгоритм условий | `engine.py`: `all`, `any`, `eq` | Исчерпывающие таблицы истинности, вложенные ветви, повторяемость результата |
| CDS-002 | Неизвестное отличается от отрицательного | Трёхзначная логика; отсутствующее значение и `null` | `test_engine.py`, `test_service.py`: unknown, false, условная визуализация |
| CDS-003 | Каждое клиническое условие связано с прямой цитатой | `catalog/rules.json` → `catalog/sources.json` | Отказ для неизвестной цитаты, несоответствующего текста/страницы и отсутствующей ссылки |
| CDS-004 | Источник и используемая редакция проверяемы | URL, редакция, страница, хеш PDF и каталога | `verify_sources.py`; отчёт содержит `source_documents` и `catalog_sha256` |
| CDS-005 | КР777 применяются в заявленной взрослой популяции | `population: adult` обязателен | Отказ для детской, неизвестной и некорректной популяции |
| CDS-006 | МРТ-находка не заменяет клинический осмотр | Четыре врачебных/контекстных факта; ограниченные origins | Отказ для `mri_model` как источника клинической оценки |
| CDS-007 | Отсутствие файла не означает отсутствие исследования | Только явное `not_performed` допускает соответствующую ветвь | Примеры 02/04; отсутствующий статус → неопределённость |
| CDS-008 | Невыполнение правила не исключает заболевание | Интерпретация `not_met` и требование врачебной проверки | Примеры 03/05 и проверка статуса review |
| CDS-009 | Неоднозначный/невалидный ввод не интерпретируется | Типы, enum, обязательное происхождение; JSON без дубликатов | Service, CLI и HTTP tests |
| CDS-010 | Локальный интерфейс сохраняет трассировку | CLI и HTTP возвращают один сервисный отчёт | CLI report, HTTP real-catalog integration |
| CDS-011 | Результаты не публикуются и не логируются автоматически | Loopback, отсутствие журналов случаев, reports вне Git | HTTP ошибки без содержимого случая; ограничения bind |

Проверка CDS-003 защищает от ошибочных ссылок внутри каталога. Верность извлечённых
фрагментов первоисточнику проверена вручную по PDF; программные тесты этого не
доказывают. CDS-005 проверяет декларацию популяции, а не фактический возраст пациента.
CDS-006 проверяет метку происхождения, а не полномочия человека, который её передал.

Открытые задачи перед клиническим применением: экспертное утверждение полной
формализации; правила опасных состояний и маршрутизация; протокол клинической
валидации; управление рисками и изменениями; контроль доступа, подлинности оценок
и сохранения истории; определение регуляторного маршрута для конкретного назначения.
